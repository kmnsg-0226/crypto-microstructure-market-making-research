# Microstructure research implementation audit

This audit was completed before downloading matching Tardis trades or inspecting any alpha
result. The chronological split is declared in
`research/specs/research_spec_draft.json` before feature evaluation.

## Reused components

- `cpp/book/OrderBook` is the canonical integer tick/lot book for live, raw replay, and Tardis
  replay. It already provides snapshots, incremental level replacement/removal, top-N access,
  uncrossed validation, and deterministic checksums.
- `cpp/historical/TardisL2Replayer` already preserves normalized CSV row order, groups level
  rows by `local_timestamp`, resets at snapshot transitions, and applies completed messages
  through the same `OrderBook`.
- `cpp/research/ResearchSnapshotExporter` already defines a deterministic zstd-compressed CSV
  writer, an exact 100ms grid, top ten levels, BBO, mid, spread, and recent aggressive trade
  quantities for the native Binance replay path.
- The retired legacy `TradeBuffer` and `TradeFlowMomentum` components defined trade imbalance as
  `(buy_qty - sell_qty) / (buy_qty + sell_qty)`. Binance `is_buyer_maker=true` maps to an
  aggressive sell and `false` maps to an aggressive buy.
- `DecimalIncrement` and `InstrumentInfo` already perform exact BTCUSDT tick/lot conversion;
  floating-point prices are not used inside the C++ book.
- Existing C++ and Python tests cover snapshot/delta semantics, sequence resynchronization,
  deterministic raw replay, exact decimal conversion, Tardis L2 resnapshot behavior, and
  environment-only CryptoHFTData credentials.

## Required modifications

- The current native Binance exporter samples by local receive time. Historical research must
  instead use Tardis exchange `timestamp`, while retaining `local_timestamp` only as ordering,
  QC, reconnect, and vendor-latency metadata.
- The existing exporter has one trailing one-second trade-volume window and no trade counts,
  notional, OFI, OBI, weighted mid, labels, or gap-aware rolling warm-up.
- A Tardis trades parser/downloader and a compact historical 100ms export are missing.
- The current Tardis validator detects replacement snapshots but does not yet emit a canonical
  feature grid. The historical exporter must reuse this parser and `OrderBook`, not implement a
  second book.
- Statistical evaluation, development-only transforms/bins, split embargo, frozen-spec gating,
  HAC inference, and OOS audit logging are not present.

## Existing export schema note

The current live/raw exporter contains top ten bid/ask price and quantity levels, BBO, mid,
spread, last trade price, and recent buy/sell volume. Some files in `data/research` were
generated by an earlier schema version; source code rather than old artifacts is authoritative.
The new research dataset therefore uses an explicit schema version and does not silently mix
old files.

## Non-duplication boundary

The historical path will reuse the C++ book and exact tick/lot types. Feature formulas and
downstream statistics will be defined once in the new research module and tested with synthetic
fixtures. The existing live collector, connection routing, snapshot synchronizer, raw storage,
and paper-trading code are not rewritten or modified for this milestone.
